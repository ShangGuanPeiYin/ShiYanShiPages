## 1. 设计目标与边界

在现有仓库的独立分支内引入 SpaceLab 的 Astro 架构、太空视觉和三维地球，提供完整实验室栏目，并迁移原站已公开资料。新版从独立源分支发布，不要求合并 `main`。默认中文、双语界面、中文正文可发布；原有英文内容保留。招生路径优先，研究、团队、论文与合作入口完整。

本 SDS 说明后续工程实现方式。本次只交付 PRD、SDS、独立审查记录及修改日志，不下载模板到项目、不安装依赖、不创建工作流、不迁移或公开资料、不更改部署服务。文中路径、接口、命令、参数和测试均为后续实现设计，不代表文件已存在或测试已通过。

不增加 React/Vue、CMS、账号、数据库、服务器端应用、在线申请或消息收集后端。日常维护通过仓库中的 Markdown/MDX 及结构化数据完成；具体维护人员是交接参数，不阻塞工程。

### 1.1 已核对的环境事实

- 原站用浏览器脚本加载 JSON 并生成页面；旧项目入口读取 `project`，为空时再读取 `slug`。
- 项目、成员、动态分别为 3、34、3 个对象，两套语言不重复计数。
- 原站论文页合并整理论文和 `htmls/publications.json`，按非空 DOI 原值去重；当前结果 242 条，历史原始记录 244 条。
- 固定模板锁文件实际锁定 Astro 6.1.9、`@astrojs/mdx` 5.0.4、Mapbox GL JS 3.23.0。Astro 要求 Node.js ≥22.12.0、npm ≥9.6.5，不能沿用 README 的 Node.js 18 最低版本说法。
- 模板源码使用占位 Mapbox Token、作者自有地图样式和不同版本的 CDN 地图 CSS；本设计替换为本站配置和与 JS 同版本的包内 CSS，不依赖作者账号资源。

### 2.1 构建与浏览器职责

内容加载、校验、草稿过滤、语言配对、静态详情路径、论文去重结果、首页排序及站点地图在构建时确定。浏览器只负责语言偏好、菜单、筛选、媒体容错、地球和照片交互，不依赖运行时 JSON 请求完成核心页面渲染。

Astro 输出 `static`，规范页采用目录型路径与尾斜杠。首次返回的 HTML 已有中文导航、正文和链接；JavaScript 不可用时仍可浏览核心资料。无需安装 UI 框架或全站客户端路由器。

### 2.3 版本策略

首次采用上游锁文件解析出的上述版本，直接依赖改为相应精确版本并同步锁文件，禁止用 `latest` 安装时静默升级。CI 和本地选择 Node.js 22 的兼容维护版本，满足 ≥22.12.0；将选定的完整补丁版本同时写入版本文件和 CI，实际选择及安装结果在实施日志记录。包管理器使用 npm，保留 `package-lock.json` 并使用 `npm ci`。

`astro check` 所需 `@astrojs/check` 与 TypeScript 要显式加入开发依赖并锁定，不能在无人值守检查时临时安装。浏览器验收依赖 Playwright 及 Chromium，仅为开发/CI 依赖，不进入站点运行时；所有新增开发依赖的最终锁定版本以实施时通过兼容校验的锁文件为准。

## 3. 内容模型与迁移

### 3.1 共同规则与语言记录

每个集合使用稳定的 `contentId`，只允许小写英文、数字和连字符；文件名为 `<contentId>.zh.md`，可选 `<contentId>.en.md`。Astro 条目 ID 保留语言后缀，通过显式 `contentId` 与 `locale` 配对，不把翻译生成第二个详情路径。

通用 frontmatter：

| 字段 | 类型与规则 |
| --- | --- |
| `contentId` | 非空稳定标识，同集合中 `contentId + locale` 唯一 |
| `locale` | `zh` 或 `en`；每个公开对象必须有中文主记录，可选英文记录 |
| `title`、`description` | 中文主记录标题非空；英文标题和两种语言摘要均允许缺省，逐字段回退，不能要求为缺素材对象虚构摘要 |
| `draft` | 布尔，默认 `false`；旧站记录迁移为 `false` |
| `image` | 可选站内资源键或 COS HTTPS URL；缺失用统一占位 |
| `tags` | 稳定标签 ID 数组，默认空；显示文字由标签资料及译文 tagLabels 按 ID 提供 |
| `sourceRefs` | 迁移来源文件、记录索引或旧稳定标识；不用于公开宣传 |

主记录 `draft=true` 时整个对象不生成公开详情、列表及 sitemap；英文记录单独标为草稿时不使用该译文，中文仍可公开。正文可为空；正文是否缺译与英文元信息记录是否存在分开判断，不制造英文翻译。标题本来为英文的论文仍可作为中文主记录的原文标题。

区分结构字段和可翻译域字段：年份、关联 ID、DOI、坐标、媒体 URL、公开状态与排序由中文主记录维护，不要求英文记录重复；标题、摘要、正文以及明确列出的可翻译字段允许英文覆盖并逐字段回退。译文文件除通用语言字段外，可提供项目 `challenge/approach/outcomes`、方向 `question/suggestedBackgrounds/materials`、新闻或博客的 `category` 及标签译名。结构字段若在译文中出现则报不支持字段，不能据此忽略合法译文。

标签结构为主记录中的稳定 `tags[]` ID 和标签资料中的中文文字，译文用以相同 ID 为键的 `tagLabels` 保存英文标签，不把翻译文字当作第二套标签 ID。迁移现有项目中英文标签时按已配对项目和数组顺序建立标签映射，保留原中文与英文文本；数组不齐或同一映射有冲突则报告并保留来源，不丢弃原文或自行翻译。筛选使用稳定 ID，显示标签按语言选择。

渲染内容仅来自受信任的仓库文件，界面和数据字符串均通过 Astro 模板转义；不将搜索输入或地理服务结果插入 `innerHTML`。Markdown/MDX 作为受信任作者维护内容，不提供任意访客上传执行入口。

### 3.2 各域扩展字段

| 数据域 | 主要字段与约束 |
| --- | --- |
| `directions` | `question`、`projectIds[]`、`suggestedBackgrounds[]`、`materials[]`、`order`；未提供的说明或数组可空；在研究页以稳定锚点呈现 |
| `projects` | `directionIds[]`、`challenge`、`approach`、`outcomes[]`、`peopleIds[]`、`video?`、`links[]`、`featured`；旧项目 ID 原样保留 |
| `publications` | `year` 必填整数，`pubDate?` 仅在真实月日存在时填写；`authorsText` 保留原作者串，`authors[]` 可选；`venue`、`type?`、`doi?`、`links[]`、`paperSite?`、`migrationOrder`；缺类型表示未分类，不推断为期刊或会议 |
| `news`、`blogs` | `pubDate?`、`eventDate?`、`sourceDate?`、`sourceDateMeaning?`、`category?`、正文；旧新闻 `date` 语义未确认时写 `sourceDate` 与 `sourceDateMeaning=unspecified`，不冒称发布日期或事件日期 |
| `collections` | `platform?`、`githubUrl?`、`huggingfaceUrl?`、其他资源链接；不把研究项目自动标为开源 |
| `markers` | `lng` 范围 [-180,180]、`lat` 范围 [-90,90]、非空 `images[]`、地点、活动类别、作者或出处、`date?`；有效公开标记才传到浏览器 |
| 团队 `team.ts` | 稳定 `slug`、本地化姓名和身份、分组、头像可选、邮箱/主页可选、`projectIds[]`、`publicationIds[]`、简介与荣誉可空 |
| 站点、招募与 FAQ | `site.ts`、`join.ts`、`faq.ts`；文本用 `{zh, en?}`；界面词典另分 `zh`、`en` 且键集合相同；FAQ 数组可空 |

集合 schema 使用真实可得字段调整模板的必填项，尤其不对只有年份的旧论文伪造 `pubDate`，不因缺封面、翻译、摘要或社交链接拒绝迁移。明确关联 ID 不存在时构建报错并定位字段；迁移阶段没有证据的关联保持空数组，不能按名字猜测。

### 3.3 一次性迁移与论文去重

迁移程序提供 `--dry-run` 检查模式和显式 `--write` 落盘模式，默认 dry-run。重复写入不得覆盖用户后续编辑；已生成对象通过迁移映射识别，若源与目标内容冲突则停止并报告，不能悄悄重置内容。

1. 配对中英文项目、成员与新闻，保留已有 slug。新建方向集合初始允许为空，研究页仍直接展示现有项目；不从项目标题虚构一个经过确认的研究方向。
2. 论文先放整理论文，再接历史数组。完全复现旧站规则：非空 DOI 的原值相同时保留首次出现的记录；空 DOI 不合并。当前输入总计 245 条，保留 242 条，3 个重复输入映射到其胜出对象。
3. 整理论文保留 `tmech-2025`。其他有 DOI 的论文 ID 为 `pub-` 加 DOI 标准化字符串的 SHA-256 前 16 个十六进制字符；标准化仅去掉 DOI URL 前缀、首尾空白并转小写，不改变第 2 步的选择规则。无 DOI 的历史条目 ID 使用对原记录键排序后稳定 JSON 的 SHA-256 前 16 字符；碰撞或同 ID 对应不同记录时停止并报告。
4. 当前已核对没有 DOI 标准化后的额外冲突。无 DOI 且标题相同的记录也不凭标题丢弃；若未来输入新增需要人工决定的冲突，将其列入迁移报告，不擅自合并。
5. 整理记录的 `authors=[]` 不应抹掉作者：将其原 `summary` 作者串写入 `authorsText`，历史作者取 `authors` 原串；有真实完整日期才填 `pubDate`。年份排序降序，同年份按真实日期再按 `migrationOrder`，未知月日不显示成 1 月 1 日。
6. 对所有源条目记录 `source file + index/id → contentId + retained/merged` 到 `src/data/migration-manifest.json`，包含 3 项目、34 成员、3 新闻及全部 245 条论文输入的去向；缺字段、缺媒体、无效外链单独报告。不自动把未复核记录置为草稿。

论文源字段的确定映射如下，不按旧渲染器只取 `title_en` 而丢掉其他已存在内容：

| 源字段 | 目标与合并规则 |
| --- | --- |
| `title_zh` | 存在真实值时作为中文主记录标题；当前历史索引 78、113 两条须保留并测试 |
| `title_en`、整理记录的 `title` | 英文标题原文保留；已有中文标题时生成对应英文元信息记录；无中文标题时中文主记录直接用英文原题，不机器翻译 |
| `summary`、`authors` | 整理记录 `summary` 为作者串的事实按当前来源映射到 `authorsText`；历史取 `authors` 原串；不拆分或重排作者顺序 |
| `year`、`venue`、`doi` | 保留原年份、发表信息及 DOI；没有真实月日时不生成 `pubDate` |
| `type` | 有来源时保留；当前 244 条历史记录全部缺省，缺值保持 `undefined`，类型筛选显示“未分类 / Unclassified”，不从期刊名推断 |
| `pdf`、`video`、`code`、`link`、`patent` | 有效链接保留原类型；空值、`#` 不渲染；原始值保留在来源记录或迁移报告 |

同 DOI 被合并记录中若有胜出记录缺失的有效题名、作者或链接，允许仅补齐胜出对象的空字段，冲突时保留胜出值并记录差异，不改变 242 个对象的计数。旧新闻的 `date` 原值写入 `sourceDate`，未确认语义时以“日期 / Date”显示；列表按 `pubDate ?? eventDate ?? sourceDate` 降序，无任何日期的内容排后。将来确认真实语义后再填写 `pubDate` 或 `eventDate`，不自动补第二个日期。

历史 `pdf/video/code/link/patent` 中有效 HTTPS 地址按原类型保留，DOI 生成论文链接；`#`、空串和示例 URL 不渲染为可点击成果。一般网站链接允许 HTTP 原值但在迁移报告列出，实验室业务媒体仍必须 HTTPS COS；不得擅自删除原始记录或自动改写到未经验证的 URL。

### 3.4 内容服务接口

下列为工程内部接口，不增加网络 API 或后端服务：

```ts
type Locale = 'zh' | 'en';
type Localized<T> = { zh: T; en?: T };
type ContentPair<T> = { id: string; zh: T; en?: T };

getPublishedPairs(collection): Promise<ContentPair[]>;
type LocalizedValue<T> = {
  value: T | null; actualLocale: Locale | null; isFallback: boolean;
};

selectContent(pair, requestedLocale): {
  primary: unknown; // 中文主记录的结构化域字段
  title: LocalizedValue<string>;
  description: LocalizedValue<string>;
  body: LocalizedValue<unknown>; // 要渲染的 Astro 内容条目
  fields: Record<string, LocalizedValue<string | string[]>>;
  tagLabels: Record<string, LocalizedValue<string>>;
};
withBase(sitePath: string): string;
withLocale(sitePath: string, locale: Locale): string;
normalizeExternalLinks(record): { label: string; href: string }[];
```

具体 TypeScript 泛型由集合类型推导，输入输出含义必须保持上述约定。`getPublishedPairs` 在构建时执行。`selectContent` 对标题、摘要、正文及允许覆盖的可翻译域字段独立选择请求语言的非空值，否则回退中文；文本去掉首尾空白后为空、数组没有有效项均视为缺值。正文通过原始 Markdown/MDX 去掉首尾空白后是否为空判定，不能只看英文文件是否存在。两边都为空时该字段返回 `value=null`、`actualLocale=null`、`isFallback=false`。英文仅有译名而无正文时，标题取英文，正文取中文且其 `isFallback=true`；正文中文也为空时隐藏正文，不显示缺译提示。缺译提示按有内容的摘要/正文及段落型域字段独立生成，正式论文原文题名和标签不因此被标成一篇文章正文缺译。公开路径按对象 ID 生成一次。

首页新闻、博客和资源用本节规定的真实日期排序；论文用年份/真实日期及迁移顺序；项目优先 `featured` 并保持源顺序，成员用负责人、研究人员、学生、校友的既有分组和源顺序。首页各摘要区最多三条，少于三条按实际数量，空集合有紧凑空状态。

## 4. 路由、双语与旧链接兼容

### 4.1 静态规范路径

栏目与详情采用 PRD 第 4 节路径。研究方向在 `/research/#direction-<id>` 呈现，项目详情仍为 `/research/<projectId>/`，避免方向 ID 与项目 ID 争用同一动态路径。成员详情由 34 个已迁移对象生成；论文详情由 242 个保留对象生成。空集合生成列表页，不生成假的详情对象；不存在的详情走静态托管 404。

独立论文页按实际内容需要添加，以 `paperSite` 关联已存在的 `/paper-sites/<id>/`；引用目标不存在时校验报错。模板示例 `humanoid-vstar` 及其大文件不直接导入 `public/`。

### 4.2 同路径语言切换

采用模板的同路径切换思想，规范页不额外生成 `/en/` 路由。语言状态优先级为有效 `?lang=zh|en` → 保存的 `mvas.lang` → `zh`。URL 参数支持显式分享英文界面和兼容旧英文入口；非法值忽略，不依赖浏览器自动推断。

构建时输出中文及可选英文的安全内容块，使用以下单一初始化契约：默认 HTML 的根 `lang=zh-CN`、界面状态为中文，仅中文或中文主记录中的原文内容可见，非选中内容块带 `hidden`；头部轻量脚本仅计算目标语言并存入 `data-requested-lang`，不能据此用 CSS 提前隐藏默认中文。正文控制器准备完毕后先确定逐字段选择结果，再在同一同步任务里设置全部块的 `hidden`、无障碍状态、界面词典及根 `data-lang/lang`，最后标记 `data-i18n-ready`。

CSS 不覆盖 `[hidden]` 强制显示翻译，也不以尚未就绪的目标语言隐藏正文。JavaScript 完全禁用、正文控制器加载延迟或执行失败时保持可读中文；偏好读取异常按中文处理。这样不承诺英文首屏零闪现，但保证初始化期间不出现正文全空或两种语言重复朗读。英文文件只有标题/摘要而无正文时，中文正文仍可见并设置 `lang=zh-CN`，显示英文的正文缺译提示；两种正文均空时隐藏该部分，不显示缺译提示。

切换语言只更新选中的内容块、界面和 `?lang=`，不重新取内容或返回首页；保留其他查询参数和锚点、筛选状态及当前内容 ID。语言操作即刻生效，写 localStorage 失败被捕获，不中断页面。站内路径用 `withLocale` 传递当前选择；重新访问从偏好恢复。

页面的中文标题及描述为构建默认，英文界面下切换到可用的英文元信息；对象标题没翻译时保留原文并翻译栏目描述。canonical 指向同一不带 `lang` 的规范路径，不声明并不存在的独立英文静态页或 hreflang 页面。sitemap 只列公开规范路径，零内容集合的栏目保留。

### 4.3 子路径规则

构建变量 `PUBLIC_SITE_URL` 表示最终源站 origin，`PUBLIC_BASE_PATH` 表示 `/` 或 `/ShIYanShiPages/` 等实际部署路径，配置映射到 Astro 的 `site`、`base` 与 `trailingSlash=always`。示例子路径大小写必须来自实际部署设置，不能据目录名猜测。

`withBase` 只接受站内路径，移除重复斜杠并保证 base 只加一次；外部 URL 不传入该函数。静态媒体使用统一资源键，运行时解析站内 base 或原样保留 COS HTTPS 地址。canonical 由 origin、base 和规范路径构造；跨页导航、CSS 背景、内容内图片和独立论文页也必须应用同一规则。

### 4.4 旧文件名兼容

构建精确文件名的静态兼容页面，不依赖托管平台重写规则：

| 旧入口 | 新目标 |
| --- | --- |
| `/index_zh.html`、`/index_en.html` | `/`，分别携带 `lang=zh/en` |
| `/htmls/research_zh.html`、`research_en.html` | `/research/` |
| `/htmls/team_zh.html`、`team_en.html` | `/our-team/` |
| `/htmls/publications_zh.html`、`publications_en.html` | `/publications/` |
| `/htmls/join_zh.html`、`join_en.html` | `/join/` |
| `/htmls/project_zh.html`、`project_en.html` | `/research/<id>/`，读取 `project`，无非空值时读取 `slug` |

全部目标补齐相应 `lang` 和 base；项目 ID 必须在构建生成的公开项目白名单中，未知或缺失时到 `/research/?missingProject=1` 并显示可理解的找不到项目提示，不默认打开第一项。兼容脚本用 `location.replace`，不接受任意目标 URL，保留允许的原锚点。

无 JavaScript 的列表兼容页提供规范列表链接；旧项目查询页提供三个真实项目的可点击列表及提示，因为静态 HTML 无法根据查询参数在服务器端选出对象。规范 `/index.html` 是首页产物本身，不另做重定向环。

## 5. 页面交互与媒体设计

### 5.1 外壳与招生路径

导航数据只维护一份，生成 PRD 的六组顶栏、移动菜单和完整页脚。父链接与展开按钮分离，点击“加入我们”进入招募页，旁边按钮展开关于/FAQ/联系；同样保证论文/资源、新闻/博客可通过键盘进入。Escape 关闭菜单并返回触发按钮；当前页可感知。

首屏身份和两项按钮是静态内容，位于地图容器之外的覆盖层，地图加载或失败不遮住按钮。地图拖动区域与按钮命中区分开，不全屏拦截页面滚动。下方严格按研究、团队、论文、新闻、开源/博客、招募顺序渲染。

研究方向的匹配字段仅展示实际提供内容；项目先全量迁入，无方向时仍可浏览。方向链接到 `/join/?direction=<id>`，仅接受已知方向 ID，选择后将方向标题编码到 `mailto:jglu@sjtu.edu.cn` 的邮件主题；仍是用户邮件应用中的可编辑邮件，不发送消息或产生后端请求。未知方向不进入主题，显示统一招募内容。

### 5.2 筛选与详情

研究按标签、团队按姓名/身份/分组、论文按关键词/年份/类型筛选，保留模板新闻、博客、开源页的搜索及分类能力。关键词使用 trim 后的大小写无关包含匹配，标签和年份按规范值精确匹配；同一控件的条件相互组合。搜索索引包含现有中英文标题、正文摘要、作者及栏目对应字段，不因界面切换丢失结果。

浏览器只切换现有卡片的可见性，保持输入焦点和结果 `aria-live` 容器。清除按钮重置本栏目的条件。集合为空时说明尚无内容；非空集合筛选成零时说明无匹配并提供清除入口。初版一次渲染现有 242 条论文，不增加服务端分页或搜索后端，后续凭测量另行决定是否调整。

### 5.3 地球控制器

初始品牌静态背景立即显示，浏览器检测 WebGL、配置 Token 后动态导入 `mapbox-gl`。使用包内 `mapbox-gl/dist/mapbox-gl.css`，与锁定的 3.23.0 JS 同版本。默认样式使用公开 Mapbox satellite-streets 样式，不沿用作者账号样式；初始全球视角，`center=[0,20]`、`zoom=1.5`、`projection=globe`。这些是设计初值，不代表实测效果最优。

状态为 `idle → loading → ready`；缺配置、不支持 WebGL、初始化异常或首次加载超过 12 秒进入 `fallback`。首次失败后不无限自动重试，按钮允许手动重试；单个瓦片错误不立即销毁已可用地球。WebGL 上下文丢失时暂停交互并显示可重试的静态主视觉。

每次初始化分配递增的 `generation`，计时器、地图 load/error 回调、动态导入和相关异步操作均捕获该值；只有它与当前值一致且尚未销毁的实例可以更新状态。进入 `fallback`、手动重试或离开页面时先递增世代使旧回调失效，再清除初始化计时器、注销监听并销毁旧地图。超时后的迟到 load 不得把 fallback 改为 ready；重试后旧实例回调不得覆盖新实例状态。进入 ready 时清除该实例计时器，所有资源清理须可重复调用。

活动标记数据构建时由公开 `markers` 导出，零标记正常创建空地球。标记搜索在本地按标题、地点、类别匹配，多结果由访客选择；不要自动用实验地点代替团队活动。弹层用真实 DOM 和转义文字构建，提供图片数量、前后切换、关闭按钮及焦点恢复；只加载当前图片。

坐标输入按“纬度，经度”解析并做范围校验，然后转换为 Mapbox 的 `[经度,纬度]`；缩放按钮沿用数值 10、12、13、16、19，其 km/m 文字仅为模板缩放档位名，不保证各纬度下的精确地面距离。地点搜索使用 Mapbox geocoding HTTP 接口，查询通过 `encodeURIComponent` 编码；提交时请求，超时 8 秒、AbortController 取消旧请求，仅最新请求可更新界面。空结果、限流、鉴权及网络失败均给出本地化提示，不影响坐标定位和其他页面。

系统减少动态效果时关闭自动旋转和非必要飞行动画；窄屏保留手动地球能力，装饰性星空降低或停止动画。切出视口或后台时暂停装饰渲染，离开页面时释放 WebGL 资源。

### 5.4 媒体规则与故障处理

视频只允许 COS HTTPS URL；新增单图 ≥5 MB 同样使用根规则指定的 COS。原视频 HTTPS 地址可直接迁移，不上传、不重新编码、不改存储桶策略。Mapbox 的地图服务资源不转存 COS。

旧图片不直接放根 `images/` 依赖运行时开发目录：实施时盘点并迁移允许入仓的小图至 `public/assets/legacy/`，通过映射保持原有名称与大小写。若已跟踪旧大图达到阈值，先生成逐文件迁移清单，实施媒体迁移时按既有 COS 规则处理；未得到有效 COS 地址前构建引用静态占位并在报告列出，不伪造地址，不把大图再次复制到 `public/`。

`Media` 组件输出图片/视频、替代文字和错误回退。视频提供 poster、`preload=metadata`、`playsinline`、控件；不在首页批量预加载全部视频。手机或减少动态效果下不自动播放。图片失败用带原始说明的文本占位，视频失败保留封面与文本；错误监听只绑定一次，避免回退图片再次失败导致循环。

## 6. 独立分支构建与发布

### 6.1 发布模型

源仓库仍为 `ShangGuanPeiYin/ShiYanShiPages`，新版发布源固定 `feat/spacelab-mvas`。托管服务创建独立项目并选择该分支，执行 npm 锁文件安装与静态构建，发布目录为 `dist/`。不引入必须合并 `main` 的步骤，不将提交静态源码到分支误认为已完成 Astro 生产构建。

托管平台账号、项目 ID、公开域名和构建环境是部署交付参数；平台选定不改变静态产物接口。若选 GitHub Pages，须另行确定隔离的站点承载方式：同仓库不能仅凭第二个分支自动提供第二个独立 Pages 站点。本设计不修改现有 Pages 来源、不新建仓库、不自动覆盖旧域名。没有隔离目标时只提供本地或托管平台预览，不称为正式发布。

将来 CI 使用仅对 `feat/spacelab-mvas` 的 push、以此分支为目标的 PR，以及手动触发；执行校验与产物构建，不自动修改旧站。初期发布由托管平台绑定该源分支或人工选择已校验产物完成，不使用带写权限 Token 的任意脚本部署。

### 6.2 配置接口

| 配置 | 默认与影响 |
| --- | --- |
| `PUBLIC_SITE_URL` | 本地 `http://127.0.0.1:4321`；正式发布必须设置为实际 origin，不能残留作者域名 |
| `PUBLIC_BASE_PATH` | `/`；子路径部署填写实际路径，统一为首尾斜杠形式 |
| `PUBLIC_MAPBOX_TOKEN` | 空；只使用浏览器可公开的受限 Token，空值构建可过且地球降级 |
| `PUBLIC_MAPBOX_STYLE` | `mapbox://styles/mapbox/satellite-streets-v12`；不使用作者专属样式 |
| `PUBLIC_RELEASE_SHA` | 本地可为 `local`；正式产物填写源分支完整提交 SHA |

所有 `PUBLIC_` 值都可以被访客看到，不存储私密部署凭据。COS 内容仅需公开媒体链接，不把 COS 密钥放入网站。正式发布检查实际构建变量，站点 origin 和 base 错误应阻止发布；没有 Token 不阻塞内容站上线，但发布报告必须标明地球处于降级而非完整地图验收通过。

### 6.3 未来开发与构建命令

以下是 SDS 中的工程接口约定，脚本需在后续实施时创建；本次没有运行这些命令。


开发和预览命令是两个分别启动的服务阶段，不同时争用 4321 端口。`test:e2e` 的 Playwright webServer 从构建产物启动预览，测试无需另手动启动服务。生产构建在目标平台环境设置第 6.2 节参数；不在本次文档中填入假的域名或凭据。

### 6.4 版本追溯与回退

构建输出 `release.json`，包含源 SHA、构建时间、origin、base、模板基准和内容计数，不包含 Token。保存成功部署的构建产物及相应配置；回退选择同一托管项目中上一份成功产物或重建对应 SHA，不重写 Git 历史、不强推、不回退 `main`。正式发布记录实际 URL、分支、SHA 和检查结果。

## 8. 设计默认、待配置参数与文档验证

本版固定的设计默认包括统一招生邮箱、仓库内容维护、同路径语言切换、规范路径、内容配对及迁移算法、静态兼容页、独立源分支和静态托管接口。它们服务于已确认需求，不将“待讨论”留给实施者随意选择不同架构。

待提供的实际参数是托管平台项目与域名、Mapbox Token/账号访问权限、后续素材、维护人员及模板/附带资产的复用依据。这些参数不阻塞文档交付；地图真实联调、正式部署及资产正式复用分别受相应参数约束，不能声称已经完成。

初版完成后，独立子 agent 已核对 PRD AC-01 至 AC-17、实际模板锁文件和旧站数据，提出 2 项重要与 3 项一般问题；v1.1 复核确认原五项闭合，又发现翻译字段限制会遗漏既有英文挑战、方法、标签和分类。本版进一步区分结构字段与可翻译域字段，补齐逐字段选择和已有译文保留检查。最终独立复核确认新增问题也已闭合，未发现本次修正引入的直接矛盾，SDS 可作为后续实施基线。伴随审查文件保留原始发现、处理与复核结论；这些结论不是运行时测试通过的声明。
