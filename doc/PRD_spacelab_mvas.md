## 1. 背景与产品目标

MVAS Lab 现有网站已具备中英文实验室介绍、研究项目、成员、论文和招募资料。本次以 SpaceLab 为新网站模板，保留其太空主题、星空动画、交互式三维地球和主要布局，建立可持续维护的实验室门户。

网站应帮助访客识别实验室的研究方向、了解真实成果与团队、找到论文和开源资源，并通过清晰的联系方式完成招生咨询或合作联系。视觉展示服务于这些访问任务，地球初始化或媒体加载不得阻止访客浏览研究内容。

本 PRD 定义后续建站需求。本次交付依次为本文件、[SDS 技术设计](SDS_spacelab_mvas.md)、独立子 agent 的 [SDS 审查记录](SDS_review_spacelab_mvas.md)及修改日志；不导入模板、不安装依赖、不迁移数据、不修改现有页面、不发布网站。

### 1.1 已确认的决定

- 采用 SpaceLab 模板及 Astro 静态网站架构。
- 保留太空主题、星空动画、三维地球与主要版式，替换为 MVAS 实验室品牌和内容。
- 首版包含模板已有的全部栏目，不因缺少素材删除栏目。
- 缺少素材时允许栏目为空，先完成页面、导航、交互和空状态，不编造数据填满页面。
- 同时保留本实验室原有的研究介绍、项目详情和加入我们需求。
- 提供中英文及桌面、平板、手机访问体验。
- 第一优先目标为招生与吸引学生；科研传播与合作展示同时保留。
- 三维地球承载真实的会议交流与团队活动足迹；无素材时保留空地球和标记浏览能力。
- 首次访问默认中文，记住访客主动选择的语言，后续访问使用已选语言。
- 首页采用地球与实验室定位同屏、研究和加入我们双入口，下方按研究、团队、论文、新闻、开源与博客、招募引导排序。
- 主导航采用首页、研究、团队、成果与资源、动态与博客、加入我们六组；次级页面归入菜单并在页脚提供完整入口。
- 正式上线时实验室介绍、研究、团队和加入我们须有真实资料；旧站现有资料先全部公开迁移、再逐项纠正，不以逐条复核完成作为迁移公开前提；其他栏目允许保留可访问的空状态。
- 按研究方向说明研究问题、代表项目、适合背景或技能和准备材料；不将建议技能虚构为硬性招生门槛。
- 首版完成双语界面，所有正文均允许只有中文；已有英文予以保留，缺译不阻塞正式发布。
- 使用独立分支 `feat/spacelab-mvas` 作为新版发布源，不要求先合并 `main`，不自动替换旧站或变更其发布配置。
- 继续遵守根目录 `AGENTS.md` 的媒体存储规定。

### 1.2 本版默认及后续配置项

按用户最新要求，本轮先完成 PRD、SDS 及独立审查，不继续以逐项访谈阻塞交付。前三轮已确认的产品选择保持不变。尚未选择的事项采用最小默认：沿用现有统一招生邮箱，通过仓库内容文件维护，不新增方向专属联系人或管理后台；栏目路径按第 4 节固定，由 SDS 定义兼容方式。以上默认属于本版设计选择，不冒充用户逐项确认。

托管平台项目、域名、Mapbox 账号及 Token、素材补充和日常维护人员属于后续配置项；账户和最终网址未提供不妨碍文档交付，但正式发布前必须填写适用的发布参数。新版从独立发布源分支构建，不意味着同一仓库会自动获得第二个 GitHub Pages 站点。

## 2. 用户与关键访问路径

| 用户 | 想解决的问题 | 网站应支持的路径 |
| --- | --- | --- |
| 潜在研究生、本科生 | 实验室研究什么，是否适合自己，如何申请 | 首页 → 研究方向或代表项目 → 团队 → 加入我们 → 邮件联系 |
| 科研同行 | 有哪些论文、方法、代码和数据集 | 论文或研究 → 详情 → 论文、代码、项目主页或数据集 |
| 合作方 | 实验室有何能力，已有何种实际项目 | 首页 → 研究项目 → 方法与真实成果 → 联系 |
| 团队成员、内容维护者 | 如何持续更新网站并避免页面数据不一致 | 编辑内容文件 → 校验 → 构建预览 → 审核发布 |

第一优先路径为潜在学生了解研究方向、判断自身匹配度、了解团队并找到招生联系入口；首页内容层级应优先服务这条路径。论文检索、科研传播和合作联系仍保留完整入口。首版不新增登录、数据库、在线申请表单、评论系统或管理后台；联系通过邮件及已有的真实外部链接完成。

## 4. 信息架构与全站规则

### 4.1 页面清单

模板实际包含关于页，也有独立论文项目页子模板，均纳入本需求。以下固定为本版规范路径；正式部署统一处理站点子路径，不因语言切换改变内容标识。

| 页面 | 规范路径 | 首版状态与职责 |
| --- | --- | --- |
| 首页 | `/` | 完整页面，实验室身份、三维地球和主要内容入口 |
| 关于我们 | `/about/` | 实验室介绍、学校归属、研究定位 |
| 研究 | `/research/` | 研究方向与项目列表，支持标签筛选 |
| 研究项目详情 | `/research/<slug>/` | 问题、方法、媒体和已有成果 |
| 论文列表与详情 | `/publications/`、`/publications/<slug>/` | 检索学术成果并访问真实外链 |
| 新闻列表与详情 | `/news/`、`/news/<slug>/` | 实验室动态、活动和公告 |
| 开源资源列表与详情 | `/collections/`、`/collections/<slug>/` | 开源项目、数据集和研究资源，可为空 |
| 博客列表与详情 | `/blogs/`、`/blogs/<slug>/` | 研究笔记、技术文章，可为空 |
| 团队与成员主页 | `/our-team/`、`/our-team/<slug>/` | 分组浏览成员及个人研究信息 |
| FAQ | `/faq/` | 常见问题，可为空 |
| 加入我们 | `/join/` | 招生方向、准备材料与邮件入口 |
| 联系 | `/contact/` | 地址、邮箱、学校及其他已确认链接 |
| 独立论文项目展示页 | `/paper-sites/<slug>/` | 保留模板能力，按真实论文需要创建，不发布示例论文内容 |
| 不存在的页面 | 站点 404 页面 | 提供首页及栏目返回入口 |

全部栏目在首版具备可访问页面，主导航按以下六组组织，页脚另提供完整栏目导航。移动端折叠菜单保留相同的分组与访问能力，不因屏幕宽度隐藏栏目。

| 顶栏分组 | 页面入口 |
| --- | --- |
| 首页 | 首页 |
| 研究 | 研究方向与项目列表 |
| 团队 | 团队列表，成员主页由列表进入 |
| 成果与资源 | 论文、开源资源 |
| 动态与博客 | 新闻、博客 |
| 加入我们 | 加入我们主入口，菜单补充关于我们、FAQ、联系 |

“加入我们”本身须可直接进入招募页；有子菜单不能使其变成只有展开作用的控件。详情页通过对应列表或内容链接进入，404 不作为导航项。

### 4.2 双语

- 在同一语义页面切换中英文，详情页尽量保留当前对象；不能将每次语言切换都送回首页。
- 导航、按钮、检索提示、空状态、错误提示、页脚和页面元信息均提供中英文。
- 模板界面通过 `data-en`、`data-zh` 等属性切换文字，不会自动翻译 Markdown 正文；正文翻译需独立维护并与同一内容标识对应。
- 只有一种语言的正文应标明实际语言及翻译未提供，不能默默显示另一语言并声称已翻译。论文题名、作者和正式名称可保留原文。
- 所有正文均允许只有中文，包括实验室介绍、研究、团队及加入我们，不以核心正文英文齐备作为上线条件。切换英文后界面为英文，缺译正文继续展示中文并明确提示；已有英文内容正常显示，不在迁移时删除。
- 首次访问且无语言选择记录时默认中文，不根据浏览器语言自动改为英文；记住用户主动选择的语言，后续访问恢复该选择。语言偏好无法保存时，本次页面切换仍须可用。

### 4.3 空内容与链接

- 无素材的栏目保留标题、简介、导航与“内容整理中”等双语空状态；不展示假卡片、虚构统计数字或模板示例成果。
- 空状态能力适用于全部栏目和本地测试；正式上线另受第 7 节核心内容门槛约束，不能将空的核心栏目作为已满足发布条件。
- 搜索无匹配结果与栏目原本为空须有不同提示；提供清除筛选入口。
- 列表为空时没有虚假的详情入口；项目、论文、成员不存在时展示可返回的不存在提示，不能显示无关对象代替。
- 没有论文、代码、个人主页等真实 URL 时不渲染该按钮；不使用 `#` 或 `example.com` 作为可操作成果链接。
- 草稿不进入公开列表、首页推荐或站点地图。内容不足三条时按实际数量显示；为零时不得出现 `01 / 00` 等异常计数。

## 5. 页面与交互需求

### 5.1 首页

首页首屏保留 SpaceLab 的太空视觉和三维地球，同时呈现实验室名称、学校归属、一句话研究定位，以及“了解研究 / 加入我们”两个主要按钮。首次进入即可辨认实验室身份并选择主要路径，不要求先操作地球或滚动后才能找到入口。

首屏下方按以下顺序呈现内容，不沿用模板以新闻开头的顺序：

1. 研究方向与代表项目，帮助学生判断研究兴趣是否匹配。
2. 团队，提供负责人和成员入口。
3. 论文，展示已有学术成果。
4. 新闻，展示真实的实验室动态。
5. 开源资源与博客摘要，分别链接到完整栏目。
6. 招募引导，再次提供加入我们入口。

地球未加载完成时，实验室身份和内容入口仍可见。滚动进入内容区不需要先完成地图操作。各摘要区链接到完整栏目；没有素材的区块可紧凑显示空状态，不用大量占位卡撑高页面。

### 5.2 三维地球与星空

- 保留旋转、缩放、地点或经纬度搜索、飞行定位及多级缩放能力。
- 以会议、学术交流与团队活动足迹为地球内容，支持真实活动照片的地理标记、标记检索、点击弹层和多图切换；标记至少有地点、坐标、标题和真实图片来源。
- 无地理素材时显示不带虚构标记的地球，保留标记与照片浏览能力；不将实验部署地点默认作为主要内容。
- 地图或定位搜索不可用时给出清楚的重试或继续浏览入口；不能影响主导航和下面的内容。WebGL 不可用时展示品牌化静态主视觉。
- 地图启用需要 Mapbox 访问配置；公开使用浏览器端受限 Token，不在客户端放私密凭据。具体账号、访问域名及额度由部署负责人确认。
- 星空保持模板风格；尊重系统“减少动态效果”偏好，减少非必要动画、自动旋转和飞行动效。手机上优先保证可读性与操作，允许降低动态效果。

### 5.3 关于、研究与项目

关于页说明实验室归属、研究领域和研究理念，不扩写未经确认的设备规模、合作关系或成果数字。

研究页展示方向说明与项目，保留标签筛选。研究项目详情包括标题、摘要、挑战、方法、图片或演示视频，以及已经提供的成果、关联成员和外部链接。可选字段为空时隐藏该节，不展示无内容标题。研究项目与开源资源可以关联，但不能把每个研究项目默认宣称为已经开源。

每个研究方向按“研究问题 → 代表项目 → 适合的背景或技能 → 申请准备材料”组织内容，帮助学生判断兴趣与能力是否匹配。背景和技能区分建议经验与真实硬性要求；具体内容由用户提供或确认，不能从项目名称自行推断招生门槛。尚无相关说明时允许待补，不阻塞旧项目先迁移公开。

### 5.4 论文与独立项目页

论文列表支持关键词、年份和类型筛选，按发表时间组织。详情显示标题、作者、发表信息、摘要、可用论文和代码链接；已提供时再显示引用信息及独立项目页入口。预印本、已录用和正式发表状态不得混用。

保留独立论文项目展示页模板，供真实研究展示方法图、视频、结果和引用。首版不要求每篇论文都建立独立展示页；模板中的示例研究、演示素材和作者信息不能作为本站正式内容发布。

### 5.5 团队与个人页

团队页保留负责人、研究人员、学生和校友分组，支持姓名、身份或分组检索。每位已公开成员可进入个人页，展示已有简介、研究方向、邮箱和真实主页链接。论文或项目关联通过内容标识建立；没有个人简介、荣誉或社交账号时留空或隐藏对应区域。缺头像时使用可识别的姓名占位，保留成员姓名与访问入口。

### 5.6 新闻、博客与开源资源

三类栏目均有独立列表、详情及日期信息，保留模板已有的浏览与筛选能力。新闻记录团队事实，博客记录研究或技术文章，开源资源提供 GitHub、Hugging Face 或其他真实资源入口。正文采用 Markdown 或 MDX 维护；明确标记的草稿及模板示例不进入正式列表。旧站资料不因尚未复核而自动变成草稿。

### 5.7 FAQ、加入我们与联系

FAQ 提供可展开的问题及回答，空集合时显示空状态；不得自行编造招生条件和政策。

加入我们展示现有博士、硕士、本科科研入口及简历、成绩单、研究经历等准备材料。招生名额、时间、申请流程等未确认信息不补写。联系按钮打开邮件应用，并提供可复制邮箱。

学生可从研究方向的匹配说明进入加入我们；招募页关联方向、代表项目和已有准备材料，避免只能看到没有上下文的邮箱。本版统一使用现有邮箱 `jglu@sjtu.edu.cn`，不新增尚无来源的方向专属联系人；邮件可带入已选方向，访客能够修改邮件内容。

联系页提供已有地址、邮箱和学校外链；不把首页三维地球当作访客必须操作的联系地图。首版不引入在线申请和消息收集后端。

## 6. 内容与技术约束

### 6.1 内容维护

采用 Astro、Markdown/MDX 内容集合及成员资料文件。使用内容结构校验发现必填字段缺失和类型错误，允许整个集合为空。运行 `build` 生成静态产物，公开站点无需数据库或常驻应用服务器。

将现有中英文 JSON 迁移到模板内容体系，迁移前建立旧标识与新标识对应关系。通用资料、两种语言与详情关联必须保持一致。模板的内容 schema 和 README 示例存在字段差异，具体实现以核对后的源码为依据，不照抄示例导致构建失败。

旧站资料默认作为公开内容迁移；内容字段和链接有效性仍进行技术校验，校验错误应列出并修正，不通过把整批记录标为草稿规避问题。后续新建内容仍可主动设为草稿，公开构建排除明确标记的草稿和模板示例。正文缺译不属于构建错误。

正式依赖安装使用仓库锁文件核对实际 Node.js 和依赖兼容性，不仅凭模板 README 的 Node.js 最低版本说明选择运行环境。Astro、Mapbox 与相关依赖版本在实施时记录；本次文档不安装或升级它们。

### 6.2 媒体存储

- 视频一律放腾讯云 COS，页面引用 HTTPS 公开地址。
- 单张图片 ≥5 MB 放 COS；小图标、Logo、头像和小封面可以保留在仓库。
- 沿用根目录 `AGENTS.md` 指定的存储桶与区域；不使用会过期的签名 URL，不提交本地视频备份。
- 视频有封面、播放控件和行内播放支持；不依赖带声音自动播放。移动端及减少动态效果模式不强制自动播放。
- 图片或视频失败后保留标题、说明与导航，提供静态封面或文本占位。
- Mapbox 在线地图瓦片及服务是地图依赖，不属于需要转存 COS 的实验室媒体。

### 6.3 兼容与部署

兼容旧中文、英文首页和 `htmls/` 下研究、项目、成员、论文、加入我们入口，保持原有 `project` 及 `slug` 查询参数所对应的对象。采用托管平台无关的静态兼容页；PRD 不要求修改现有域名或立即替换线上站点。

所有静态资源与页面链接必须适配最终域名及子路径。从独立源分支 `feat/spacelab-mvas` 安装锁定依赖、构建并发布 `dist/`，不依赖合并 `main`。采用单独的托管项目或预览地址与旧站隔离；同仓库 GitHub Pages 的已有站点设置不自动修改。具体托管账号、项目与域名在发布前配置。先提供本地预览，再进行测试环境验收，最后才安排正式发布。

### 6.4 可访问性、可发现性与性能

- 所有核心功能支持键盘，焦点可见；移动菜单及弹层支持关闭和合理的焦点恢复。
- 图片有替代文字；装饰性星空不干扰屏幕阅读；筛选结果数量和错误提示可被感知。
- 页面具备合适的标题、描述、语言标识、语义结构及 404；站点地图不包含草稿和模板示例。
- 图片采用合理尺寸及延迟加载，地图和媒体不阻塞主要访问路径。不得自动下载全部视频或一次性预取所有详情媒体。
- 首版先验收可访问和无阻塞行为；没有实际测量前不承诺具体加载速度、SEO 排名或性能改善幅度。

## 7. 分期与完成定义

全部栏目都属于首版功能范围，下面是实施顺序，不将博客、FAQ 或开源栏目移出首版。

| 阶段 | 交付物 | 完成条件 |
| --- | --- | --- |
| M0 文档基线 | 本 PRD、SDS 和独立审查记录 | 用户决定已回填，设计默认明确，重要审查问题修正；后续配置项单独列出 |
| M1 模板基础 | Astro 工程、品牌外壳、全站导航、太空与地球视觉 | 本地可构建预览；无地图配置时其他内容仍可访问 |
| M2 完整页面能力 | 全部栏目、必要详情页、双语、搜索筛选、空状态 | 所有栏目可访问；真实内容和空集合两类数据都可运行 |
| M3 现有资料迁移 | 现有资料公开迁移、纠错清单、媒体引用和旧入口兼容 | 迁移数量与来源对账；不混入模板示例或虚构资料；不增加整批草稿或逐条先审的公开前置条件 |
| M4 验证与发布 | 测试报告、测试环境预览、发布及回退说明 | 完成功能验收，并单独取得正式发布所需确认 |

功能完成表示页面与交互具备能力、空状态成立且构建可部署；素材完成表示实验室确认并提供了足够内容。二者分别记录，不能用“素材未齐”掩盖缺失功能，也不能把空页面当作内容已完成。本地与测试环境允许全部栏目暂为空，用于验证页面能力。

正式上线须满足以下内容门槛：实验室介绍、研究、团队和加入我们有真实资料，访客能够了解实验室身份、研究内容、团队及招生联系路径。第三轮进一步明确，现有实验室资料可先全部公开，再逐项纠正，不要求全部人工复核或核心正文英文齐备后才公开；保留原日期及来源，不把迁移完成表述为时效性复核完成。博客、开源资源、FAQ 等其他栏目允许继续显示“内容整理中”，栏目与导航保持可访问。
