# MVAS 实验室网站全站改版设计

日期：2026-09-22

## 1. 目标

将机器视觉与自主系统实验室（MVAS Lab）现有中英文静态网站整体改造成具有鲜明学术身份、工程现场感和现代编辑感的实验室门户。

设计借鉴 MIT Biomimetic Robotics Lab 网站的内容节奏：以大型研究影像作为第一视觉层级，以简洁导航、强标题、充足留白和直接的研究入口组织内容。本站不复制 MIT 的品牌资产、文字、布局细节或交互实现，而是建立以上海交通大学红为核心的独立视觉体系。

改版覆盖：首页、研究、项目详情、成员、学术成果和加入我们，以及对应的中文和英文版本。

## 2. 成功标准

- 用户进入首页后能迅速识别实验室归属、研究主题和代表项目。
- 研究项目、成员与论文在桌面端和移动端均可清晰浏览与筛选。
- 中文和英文页面共享同一套组件、布局和交互，不产生两套独立实现。
- 页面继续作为无需构建工具的静态网站部署。
- 键盘导航、焦点状态、替代文本、颜色对比和减少动态效果设置得到支持。
- 图片、视频或 JSON 加载失败时，页面仍保留可理解的内容和导航。

## 3. 视觉方向

### 3.1 核心概念

“交大学术红 × 工程纪实”：以暖白纸面承载内容，以深交大红建立学校身份，以炭黑和金属灰表现机器人与工程研究的精密感。

### 3.2 色彩

- 主色：深交大红 `#9E1B32`
- 深色强调：炭黑 `#171717`
- 页面背景：暖白 `#F5F2ED`
- 内容表面：白色 `#FFFFFF`
- 次级文字：中性灰 `#66615B`
- 分隔线：浅暖灰 `#D8D2CA`

最终色值可在实现中为可访问性进行小幅调整，但必须保持交大红为唯一高饱和强调色。

### 3.3 字体与构图

- 不依赖在线字体；使用适合中英文混排的本地字体栈。
- 标题紧凑、粗重，使用短行和明显字号层级。
- 正文保持舒适行宽和较高行距。
- 版式以大幅影像、非对称网格、细线、编号和留白为主。
- 卡片避免大圆角、渐变和夸张阴影，保持学术编辑风格。

## 4. 信息架构

### 4.1 全站外壳

- 顶部品牌区展示实验室标识、中文或英文名称及上海交通大学归属。
- 主导航提供首页、研究、成员、成果和加入我们入口。
- 中英文切换保留当前页面语义对应关系。
- 桌面端采用横向导航；移动端采用可访问的折叠菜单。
- 页脚统一展示地址、邮箱、学校链接和版权信息。

### 4.2 首页

1. 全宽首屏项目展示：使用本地视频或高质量封面，叠加实验室定位、项目标题和行动入口。
2. 实验室使命：用简短文字说明机器视觉、机器人和自主系统的研究方向。
3. 重点研究：展示三个代表项目，使用大图和非对称布局。
4. 最新动态：展示最近三条实验室新闻。
5. 招募引导：说明开放方向并链接到加入我们页面。
6. 联系信息：在页脚前形成清晰的到访与邮件入口。

### 4.3 研究页

- 页面开头解释实验室整体研究范围。
- 项目以编号、大幅封面和简短摘要组成编辑式网格。
- 保留按研究标签筛选功能。
- 每个项目都可进入独立项目详情页。

### 4.4 项目详情页

- 大幅封面或演示视频作为项目主视觉。
- 展示项目名称、标签和摘要。
- 分区说明挑战、方法和成果。
- 真实存在时展示论文、代码、视频等外部链接。
- 不存在链接时不渲染占位按钮。

### 4.5 成员页

- 实验室负责人或核心教师使用更高层级的重点展示。
- 其他成员按现有分组展示为规整人像网格。
- 保留按姓名、角色和分组搜索功能。
- 缺失照片时展示统一的文本或图形占位。

### 4.6 学术成果页

- 以年份为主要视觉索引组织论文。
- 每条成果突出标题、作者/摘要、会议或期刊和可用链接。
- 保留关键词、年份和类型筛选。
- 减少传统卡片边框，使用时间轴和分隔线形成阅读节奏。

### 4.7 加入我们页

- 页面介绍实验室对学生和研究合作者的期望。
- 分别列出开放方向、建议准备材料和联系邮箱。
- 联系按钮直接使用邮件链接，不增加在线表单或后端依赖。

## 5. 技术设计

### 5.1 架构

保留当前原生 HTML、CSS 和 ES Modules 架构，不引入前端框架、打包器或新运行时依赖。

- HTML 文件负责语言和页面类型入口。
- `assets/js/site-shell.js` 负责统一导航与页脚。
- `assets/js/app.js` 继续根据 `data-page` 渲染各类页面。
- `data/zh` 和 `data/en` 继续作为中英文内容来源。
- CSS 令牌、基础样式和站点组件样式按职责组织。

### 5.2 内容与数据流

1. 页面入口通过 `data-lang` 和 `data-page` 标识语言与页面类型。
2. 应用根据语言加载对应 JSON 数据。
3. 页面渲染器对数据进行验证和 HTML 转义。
4. 筛选器仅在浏览器内操作已加载数据，不请求后端。
5. 项目详情继续通过查询参数中的项目 slug 查找数据。

### 5.3 媒体资源

- 根据用户最新决定，不再强制使用腾讯云 COS。
- 图片和视频可以作为项目本地资源，用相对路径引用。
- 视频使用 `poster`、`preload="metadata"` 和 `playsinline`。
- 移动端和开启减少动态效果的设备不强制自动播放视频。
- 项目应避免无目的地重复存放相同媒体文件。

## 6. 交互与动效

- 首页首屏支持项目切换；优先使用简单、可控、可键盘操作的实现。
- 导航在滚动后保持可见，并通过背景和边框确保可读性。
- 链接和按钮使用红色填充、红色线框或文本下划线形成明确层级。
- 内容进入视口时采用轻量淡入和短距离位移动画。
- `prefers-reduced-motion: reduce` 下关闭非必要动画、自动切换和自动播放。
- 所有交互控件提供清晰的悬停、当前、聚焦和禁用状态。

## 7. 响应式设计

- 桌面端使用宽屏编辑式布局与不对称项目网格。
- 平板端降低列数并缩小标题尺度。
- 手机端导航折叠，所有主要内容转为单列，触控目标不少于约 44 像素。
- 首屏在手机端优先展示静态封面和简短标题，避免视频影响性能与流量。
- 表单筛选控件在窄屏下占满可用宽度。

## 8. 错误处理与可访问性

- JSON 加载失败时显示可见、可理解的页面错误信息。
- 项目 slug 不存在时显示 404 状态和返回研究页入口。
- 图片使用有意义的替代文本；纯装饰图使用空替代文本。
- 菜单、轮播、筛选器和语言切换支持键盘操作。
- 页面保留跳至主要内容链接、语义标题层级和实时状态提示。
- 焦点样式必须始终可见，不能仅依赖颜色表达状态。

## 9. 测试与验收

- 运行现有数据客户端和静态路由测试。
- 为新增的首屏切换、菜单状态或媒体回退逻辑补充针对性测试。
- 检查所有中英文入口及项目详情链接。
- 在桌面、平板和手机宽度下检查首页及每类栏目页。
- 检查键盘导航、减少动态效果模式、视频无法播放和图片缺失场景。
- 检查本地静态服务器和最终部署环境中的相对资源路径。

## 10. 非目标

- 不增加 CMS、数据库、账号系统或在线申请表单。
- 不迁移到 React、Vue 或其他框架。
- 不复制 MIT 网站的商标、Logo、照片、文字或源代码。
- 不在本次改版中虚构成员、论文、新闻或研究成果。
